# 评测结果（v0.2，2026-10-30）

运行配置：**只用确定性取证 + OCR，没开 VLM**（VLM 用来补强"实拍 / AI / 3D"的区分、AI 图和真实照片的区分，以及轻音效）。复现命令见文末。

## 1. 底层画面制作方式（8 类，按镜头时长加权）

| 集合 | 视频数 | 准确率 | 切点 F1 | 独立性 |
|---|---|---|---|---|
| `labels.yaml`（调参集） | 15 | **99.9%** | 1.00（2 条有真值，含 14 处 0.25s 交叉溶解） | 规则在这批样本上设计 |
| `holdout.yaml` | 9 | **99.6%** | — | 首轮错了 2 处，据此加了帧率相关规则，已不完全独立 |
| `holdout2.yaml` | 7 | **99.8%** | — | 制作方式规则定稿后才第一次运行 |

调参集的混淆矩阵（秒）：实拍 16.0 全对；AI 视频 141.2 全对；3D 66.5 全对；代码渲染 157.9 对、0.4 错判为 3D；录屏/截图 19.0 全对；静帧 48.2 全对。

## 2. 用户真实素材（镜头里有没有实拍 / 截图 / 录屏 / 照片，按时长加权）

| 集合 | 准确率 | 说明 |
|---|---|---|
| labels | 97.6% | 唯一错误：mediank 的暗色半透明 NASA 背景照片漏检（已知局限） |
| holdout | 99.6% | 首轮有 2 处误报：浅色代码画面的字幕被当成截图；3D 毛发被当成嵌入视频。修复后的结果 |
| holdout2 | 98.1% | **首轮只有 75.6%**：字幕带被当成照片/视频；嵌入图片默认算作"真实"。修复后已不独立。剩余错误：暗色主题网页截图漏检 |

修复内容：
- 文字按单帧计数，避免不同时刻的字幕被累加。
- 字幕带不参与照片/视频判断。
- 嵌入的照片/视频片段默认标为"真实还是 AI 待确认"，只有截图和录屏直接算真实素材。
- 3D 画面里只认截图面板。

## 3. 声音

| 项 | 结果 | 真值来源 |
|---|---|---|
| 有无人声 | 5/5 | capsule-cinema 的 tts.py、口播视频 |
| 有无 BGM | 4/4 | bgm.py、bgm_fit.json |
| BPM（±4%，含半速/倍速） | 2/2（110.0 / 112.3 vs 真值 110.15） | bgm_fit.json |
| 调性 | 2/2（D major） | bgm_fit.json |
| 有无音效（≥3 处） | 2/4 | cues.py、素材清单 |
| 音乐来源 | 2/5（见下） | Suno 生成记录、曲库下载记录 |

**音效是确定性层的短板**：在咸鸭蛋的人声 + BGM 混音里，对照 cues.py 的 110 个音效真值，信号特征完全区分不了音效和语音/音乐起音（精度约 0.2，与随机相当）。所以现在只在人声之外、且极其突出的瞬态上给出"低置信候选"，**完整的音效清单交给 VLM（Gemini 能听）**。

**音乐来源**按"视频形式先验 + 证据"判断（规则见 `skills/rea-video/references/audio.md`）。不开 VLM、不给平台信息时：

| 视频 | 形式 | 真值 | 判断 |
|---|---|---|---|
| qing_hiphop_mv | AI 说唱 MV（干声副歌重复 0.26） | Suno v6 | AI 生成 52% ✓ |
| mediank_pure_data | 纯配乐 | 曲库 manten diloty | 现成曲库 60% ✓ |
| monkey_wine_v3 / salted_egg / birdnest | TTS 旁白 + BGM（干声副歌重复 0.00） | Suno 生成 | 现成曲库 52% ✗ |

三个错例是**先验本身的局限**：AI 工作流做出来的普通视频，BGM 也常是 Suno 生成的，而 Suno 器乐和曲库器乐从信号上分不开。之前 3/3 是因为"满屏音乐 + 有人声"误把 TTS 旁白当成 MV，属于碰对；现在加了唱/说区分，判断理由对了，准确率反而如实下降。纠正这三条要靠平台音乐标签（`--meta`）或听歌识曲，所以报告里普通配乐一律写"倾向曲库，待确认"。注意唱/说的阈值是看过 qing MV 之后定的，这条属于开发集。

**人声分离**（`stems/`）：把咸鸭蛋的一句 TTS 叠在它的 Suno BGM 上（人声高 6 dB），分离 SDR 人声 19.7 dB、配乐 19.7 dB；纯 BGM 漏进人声轨 −42.5 dB。mediank 的键盘音效会落进人声轨（瞬态音效的已知去向）。说唱 MV 在混音上测的持续音高是 0.44，在干声上只有 0.24——混音上的数字被伴奏的长音抬高了，所以现在唱/说一律在干声上测。

## 4. 平台转码视频（OiiOii 文章里的 10 条，开发集）

`eval/articles.yaml`：从两篇公众号文章下载的微信转码版（30fps、二次压缩）。真值来自文章作者说明 + 人工看画面。v0.3 的规则是看过这批视频后加的，所以这是开发集。

| 视频 | 真值 | v0.2 | v0.3 |
|---|---|---|---|
| v11 TikTok 带货原片 | 实拍 | AI 100%（0.0） | 实拍 100%，标"实拍还是 AI 待确认"（1.0） |
| v09 Gemini 发布片 | 2D UI 动效 | 代码 63% + 3D 37%（0.63） | 代码 81% + 3D 19%（0.81） |
| v10 OiiOii 产品片 | 代码 UI 动效 | 代码 78% + 3D 17%（0.83） | 代码 92% + 3D 4%（0.96） |
| v04 推广片原片 | 3D 元素 + 文字动效 | 3D 65% + AI 35%（0.65） | 不变（0.65） |
| 其余 6 条 AI 视频 / 拼屏 | — | 全对 / 0.8 | 不变 |
| **平均** | | **0.79** | **0.92** |

v0.3 的三处修改：
1. 识别平台转码（元数据 `Tencent CAPD MTS` / `Wxmm_` / `vid:v…`）。转码后噪声证据失效，"没有噪声"不再推向 AI；清晰度节奏（会被转码的 GOP 结构伪造）不再当插帧证据。
2. 整片级帧率证据：30fps 文件里，实拍类镜头 ≥70% 时长没有重复帧 → 倾向手机直出（生成模型多输出 24fps，转 30fps 后有 20% 重复帧）。
3. 几乎无彩色、只用个位数颜色的平面画面判为界面/文档，不判 3D。

三个评测集回归：制作方式 99.9% / 99.6% / 99.8% 与 v0.2 完全一致。

## 已知局限

1. 实拍样本只有 3 条（都是 60fps 抖音手机视频）；没有真实的 Ken Burns 样本，只在合成视频上测过。
2. 暗色/半透明的背景照片、暗色主题网页截图漏检；实拍或 AI 画面上叠加的商品图和 Logo 不做确定性检测，依赖 VLM。
3. 嵌入图片是真实照片还是 AI 图，确定性层判断不了。
4. VLM 路径只用假服务器测过端到端，还没有在真实 Gemini 上跑过评测。
5. 音乐来源：普通视频里的 AI 生成 BGM 判断不出来（见上）；AI MV 样本只有 1 条。

## 2026-10-30：第一次用真实 Gemini 跑 VLM，并加入「agent 看图复核」

数据：`eval/articles.yaml`（10 条微信转码视频，**开发集**，规则看过这批视频）。VLM 结果来自 zcode 盲测第 2 轮（`gemini-3.1-pro-preview-pc`，每条都生效），agent 复核来自同一轮 zcode 的 `rea-video review / apply-review` 答案。用缓存结果重新融合，不再调用 API。

| 组合 | VLM 权重 1.0（旧） | VLM 权重 0.7（新） |
|---|---|---|
| 只用确定性取证 | 0.886 | 0.886 |
| + Gemini VLM | 0.888 | 0.888 |
| + agent 看图复核 | 0.988 | **1.000** |
| + VLM + agent | 0.915 | 0.984 |

（按时长加权的准确率；真实素材准确率四种组合都是 1.0）

- Gemini 在 3D / UI 动效类视频上有帮助（v04 0.65→1.0、v08 0.8→1.0、v09 0.81→0.98），但会把卡通 3D 风格的 AI 视频判成 3D 渲染、把画进画面的游戏界面判成录屏（v01 1.0→0.13、v12 1.0→0.56、v13 1.0→0.44），而且置信度给到 0.9–1.0，压过了 24→30 重复帧等帧率证据。
- 改动：融合时 VLM 权重 1.0→0.7（`classify.VLM_WEIGHT`）；融合结果必须是确定性层或模型排前两名的类别（修 v01 最后一镜三方都没投却得出"实拍"）；`review_tasks.json` 只给 agent 看确定性结果，不给 VLM 答案，避免被带偏。
- 只有 10 条开发集视频，权重没有往更低调（0.5 在这批上更高，但怀疑过拟合）。下一步：在 labels / holdout 上跑一次 `--vlm`，确认 0.7 不伤别的视频。
- labels 0.999 / holdout 0.996 / holdout2 0.998 不受影响（这些评测不开 VLM）。

## 2026-10-30：留出集验证（zcode + Gemini VLM + agent 看图复核）

数据：`eval/holdout.yaml`（9 条）+ `eval/holdout2.yaml`（7 条），这 16 条没参与过 VLM 权重和复核流程的调参。zcode 按 JOB.md 盲测（视频改名 h01–h16，对照表在 `out/agent_eval/zcode/runs_holdout/mapping.tsv`），`--vlm`（16/16 生效）+ `review / apply-review`。h09（lulukong_b）zcode 自身报错中断，没写复核，只计工具 + VLM。

| 组合 | holdout | holdout2 | articles（开发集） |
|---|---|---|---|
| 只用确定性取证 | 0.996 | 0.998 | 0.886 |
| + Gemini VLM | 0.989 | 0.965 | 0.888 |
| + agent 看图复核 | 0.996 | 0.968 | 1.000 |
| + VLM + agent（改前） | 0.998 | 0.988 | 0.984 |
| + VLM + agent（加「工具 + 一方看图」多数规则后） | **0.998** | **0.998** | **0.988** |

- 只开 VLM 在留出集上是负收益（holdout2 0.998→0.965）：Gemini 把文字卡片判成静帧/截图推拉，把毛绒 AI 角色判成实拍/3D，置信度 0.85–1.0。
- 改前 holdout2 唯一的退步是 lulukong_c 最后一镜：工具判 AI（0.46）、zcode 判 AI（0.83），只有 Gemini 判实拍（0.85），结果却是实拍。原因是 VLM 和 agent 的意见先平均再融合，Gemini 给 AI 只有 0.05，把 zcode 那一票抵掉了。
- 改动：`pipeline._majority` + `classify.fuse(majority=...)`。工具首选和 VLM、agent 中恰好一方一致时，最终类别必须是它（帧冻结等硬约束仍优先）。反过来 VLM 和 agent 一致反对工具时**不**强制：试过三方任意多数，articles 从 0.984 掉到 0.919、dual_role_realcat 1.0→0.83，两个看图模型常把同一画面看错成同一类。
- 「证据不足，待确认」：转码 + 24fps 源 + 无 AIGC 标识的 AI 视频（capybara_a、lulukong_a/b/c）都被标出、置信度封顶 0.7；手机原生 30fps 的实拍（douyin_live_breakfast）、代码/3D 类视频不受影响。
- zcode 的 FINAL 结论：15 条完成的里 14 条制作方式正确；dual_role_realcat 写成"静态图推拉·真实截图 56% + AI 44%"（真值是代码模板卡片 + 真实截图 + AI），真实素材判断对。
- labels 0.999 / holdout 0.996 / holdout2 0.998（不开 VLM 的回归）不变。
- 结论：开 VLM + agent 复核在三组数据上都不低于只用工具，在开发集上大幅更高；只开 VLM、不做 agent 复核时会变差，SKILL.md 里"能看图的 agent 必须做 review"的要求要保留。

## 2026-10-30：只有一个看图来源时加限制；加入用户记忆

问题：只开 VLM、不做 agent 复核时，比只用工具还差（holdout2 0.998→0.965）；只有 agent 看图、没有 VLM 时，holdout2 也降到 0.968。

改动（`pipeline._vlm_gate`）：只有一个看图来源时（只有 VLM 或只有 agent），它的首选必须在工具前两名里；工具对 AI / 实拍 / 数字人有把握（≥0.65 且领先 ≥0.25）时不采用；转码 24fps 素材、没有手机原生 30fps 证据时，不采用"实拍"。两个来源都有时不受影响，由 `_majority` 决定。

| 组合 | holdout | holdout2 | articles（开发集） |
|---|---|---|---|
| 只用确定性取证 | 0.996 | 0.998 | 0.886 |
| + VLM（改前 → 改后） | 0.989 → **0.996** | 0.965 → **0.998** | 0.888 → **0.996** |
| + agent（改前 → 改后） | 0.996 → 0.996 | 0.968 → **0.998** | 1.000 → 1.000 |
| + VLM + agent | 0.996 | 0.998 | 0.988 |

（holdout 的 VLM + agent 从 0.998 变为 0.996：h09 没有 agent 复核，现在按"只有 VLM"处理。）

- 比较过的其他做法：只在工具没把握时用 VLM（holdout2 0.965）、只要求在前两名里（holdout 0.987）、把 VLM 概率摊平到 0.3（holdout2 0.974）。最终方案是"前两名 + AI/实拍轴保护"。
- 注意：这条规则是在这三组数据上选出来的，三组都不再是"没见过的视频"。需要一批新视频复核，用户纠正导出的样本（`rea-video memory --export-labels`）可以作为来源。
- labels 0.999 / holdout 0.996 / holdout2 0.998（不开 VLM 的回归）不变。
- 新增用户记忆（`rea_video/memory.py`，存在 `~/.rea-video`）：`correct` 记录纠正并立即改结论，同一文件再拆时自动套用；同类纠正出现 2 次以上，会在复核任务和 `summary` 里提示；`prefs` 记默认参数和自由文字偏好；`memory --export-labels` 导出评测样本。评测（`rea-video eval`）不读用户记忆。
